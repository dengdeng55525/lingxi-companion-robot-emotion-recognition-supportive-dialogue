# 灵犀早教陪护机器人技术报告

日期：2026-07-09  
项目定位：面向儿童的早教陪护机器人，具备视觉感知、语音交互、情绪陪伴、物体认知学习、家长端观察和移动控制能力。

> 说明：本报告按未来迁移到高算力板子的目标来描述系统架构。视觉推理统一表述为“本地模型”或“本地视觉推理服务”，不依赖特定云端平台概念。

## 1. 系统概述

灵犀系统由三个核心层组成：

1. 感知层：摄像头视频流、语音输入、情绪识别、物体识别。
2. 思考层：语言模型理解用户意图，结合视觉、记忆、对话历史生成结构化决策。
3. 执行层：语音回复、底盘运动控制、家长端数据记录与展示。

当前代码主要分布在两个工程中：

| 模块 | 目录 | 作用 |
|---|---|---|
| 视觉与前端工程 | `/home/lzc/yolov5_emotieff_vgaf_windows` | 摄像头视频采集、视觉推理结果整理、情绪/物体识别前端、家长端 API 与前端 |
| ROS 语音与控制工程 | `/home/lzc/catkin_ws/src/robot_voice` | 语音识别、AI 对话决策、语音播报、底盘 `/cmd_vel` 控制 |

## 2. 视觉模型一：人脸情绪识别模型

### 2.1 模型组成

情绪识别链路由两级模型组成：

1. 人脸检测：YOLO5Face  
   代码入口：`pipeline_face_emotion.py` 中的 `YOLOFaceDetector`

2. 表情分类：EmotiEffLib  
   代码入口：`pipeline_face_emotion.py` 中的 `FaceEmotionPipeline`

人脸检测负责从整帧图像中定位人脸框；情绪分类模型对人脸区域进行表情分类，输出主情绪、置信度和各类别概率。

典型输出字段：

| 字段 | 含义 |
|---|---|
| `bbox` | 人脸框坐标 |
| `crop_bbox` | 扩展后送入情绪模型的人脸区域 |
| `face_confidence` | 人脸检测置信度 |
| `emotion` | 主情绪标签 |
| `confidence` | 主情绪置信度 |
| `probabilities` | 多情绪类别概率分布 |

当前情绪类别主要覆盖：

```text
happy, sad, angry, neutral, surprise, fear, disgust, unknown
```

在给 AI 节点使用的轻量 JSON 中，部分情绪会被归并成更适合陪护决策的标签：

| 原始类别 | AI 陪护侧含义 |
|---|---|
| `happy` | 开心 |
| `sad` | 低落 |
| `angry` | 生气 |
| `fear` / `disgust` | 紧张、抗拒、需要关注 |
| `surprise` | 兴奋、惊讶 |
| `neutral` | 平静 |

### 2.2 推理流程

情绪识别流程如下：

```text
视频帧
  |
  v
YOLO5Face 人脸检测
  |
  v
选择人脸框并扩展 crop 区域
  |
  v
EmotiEffLib 情绪分类
  |
  v
生成 faces/main_person/probabilities
  |
  v
写入完整视觉 JSON 与轻量视觉 JSON
```

完整视觉 JSON：

```text
/home/lzc/yolov5_emotieff_vgaf_windows/outputs/latest_emotion.json
```

AI 和 RoboEyes 读取的轻量 JSON：

```text
/home/lzc/.ros/latest_emotion.json
```

### 2.3 高算力板迁移方式

未来迁移到高算力板时，推荐将 YOLO5Face + EmotiEffLib 和物体检测服务一起部署在板端，保留现有 HTTP API 与 JSON 格式。这样上层 ROS、前端和家长端无需大改，只需要把视频推送目标改为板端本地服务地址。

## 3. 视觉模型二：物体识别模型

### 3.1 模型职责

物体识别模型负责识别画面中的常见物体，并输出：

| 字段 | 含义 |
|---|---|
| `class_id` | 物体类别 ID |
| `class` | 物体类别名称 |
| `confidence` | 置信度 |
| `bbox` | 物体框坐标 |
| `inside_roi` | 是否位于关注区域内 |

在当前系统中，物体检测结果和情绪识别结果统一进入同一份视觉 JSON：

```json
{
  "faces": [],
  "objects": [
    {
      "class_id": 0,
      "class": "person",
      "confidence": 0.90,
      "bbox": [188, 176, 393, 381],
      "inside_roi": true
    }
  ]
}
```

从本项目角度看，物体模型由本地视觉推理服务承载，`send_webcam_http.py` 负责将摄像头帧推给该服务，再把服务返回的 `objects` 字段写入项目 JSON。

### 3.2 物体识别与学习概念的区别

系统现在区分“检测到物体”和“孩子学到了一个概念”：

1. 物体检测：视觉模型每帧都可以输出 `objects`。
2. 学习概念：只有孩子主动表达求知欲，例如“灵犀，这是什么？”、“眼前是什么？”、“我想知道这个”，并且语言模型判断 intent 为 `object_learning_query`，同时视觉 JSON 中存在 `objects`，才写入学习事件。

学习事件日志：

```text
/home/lzc/.ros/ai_learning_events.jsonl
```

这样可以避免把所有路过画面的物体都算作学习成果，更符合早教场景：只有孩子主动提问并完成一次认知交互，才计入“今日学习概念”。

## 4. 视频采集与本地模型推理服务

### 4.1 视频来源

当前主要视频来源是 ROS 图像话题：

```text
/camera/rgb/image_raw
```

通过 `web_video_server` 转为 HTTP/MJPEG 视频流：

```text
http://127.0.0.1:8080/stream?topic=/camera/rgb/image_raw
```

`send_webcam_http.py` 支持两类输入：

| 输入方式 | 参数 |
|---|---|
| 本地摄像头编号 | `--camera-index 0` |
| HTTP/MJPEG 或 RTSP 网络视频流 | `--camera-url "http://.../stream?topic=..."` |

当 `--camera-url` 非空时，优先使用网络视频流；为空时沿用本地摄像头编号。

### 4.2 最新帧覆盖机制

为降低 MJPEG 或 RTSP 缓冲造成的延迟，采集线程采用“最新帧覆盖”策略：

```text
采集线程持续读取视频源
  |
  v
只保存最新一帧和 sequence
  |
  v
上传循环按 upload-fps 取最新帧
  |
  v
同一 sequence 不重复上传
```

该机制不会建立无限队列。上传过程中到达的新帧会覆盖旧帧，因此系统更关注实时性而不是逐帧完整处理。

### 4.3 JSON 转换与落盘

视觉服务返回推理结果后，`send_webcam_http.py` 会执行三步：

1. 将本地视觉服务返回结果转换成项目统一格式。
2. 写入完整视觉 JSON：`outputs/latest_emotion.json`。
3. 写入 AI 读取的轻量 JSON：`~/.ros/latest_emotion.json`。

轻量 JSON 重点保留：

```json
{
  "timestamp": 1783349000.0,
  "face_count": 1,
  "dominant_emotion": "happy",
  "confidence": 0.82,
  "scores": {
    "happy": 0.82,
    "sad": 0.01,
    "angry": 0.01,
    "neutral": 0.16
  },
  "object_count": 1,
  "objects": []
}
```

### 6.2 情绪趋势分析策略

家长端情绪分析不是简单统计最高频情绪，而是按早教陪护场景设置关注优先级：

1. 最高优先级：生气、低落、抗拒、紧张等需要家长关注的情绪。
2. 中等优先级：开心、惊讶，表示积极互动或兴趣变化。
3. 最低优先级：平静、无明显表情。

这样即使“平静”数量最多，只要最近一段时间出现过愤怒、悲伤、抗拒等信号，趋势文案也会优先提醒家长结合当时对话和活动场景观察。

### 8.2 双路由机制

系统保留了“简单指令快速执行、复杂指令交给模型思考”的双路由策略。

本地快速规则适合：

| 类型 | 示例 |
|---|---|
| 单步短动作 | “前进”“左转”“后退一米” |
| 停止 | “停止”“停车” |
| 时间日期 | “现在几点”“今天几号” |
| 简单记忆 | “记住你的名字叫灵犀” |
| 找人 | “灵犀，找一下我” |

语言模型思考适合：

| 类型 | 示例 |
|---|---|
| 多步连续动作 | “先向前 10 米，再左转 300 度，再跳舞” |
| 需要顺序规划的动作 | “先前进，再后退，然后转一圈” |
| 超过单步安全上限的动作 | “前进 10 米”“左转 300 度” |
| 早教知识问答 | “你能背一首古诗吗？” |
| 纠错类问题 | “杜甫的静夜思” |
| 视觉物体求知 | “灵犀，这是什么？” |

### 8.3 模型输入上下文

AI 节点向语言模型传入结构化上下文：

```json
{
  "user_text": "灵犀，这是什么？",
  "vision": {
    "dominant_emotion": "happy",
    "objects": []
  },
  "vision_age_seconds": 0.5,
  "vision_emotion_cue": {
    "emotion": "happy",
    "confidence": 0.82
  },
  "recent_replies": [],
  "recent_user_texts": [],
  "memory": {},
  "robot_state": {
    "motion_interface": "text_command_to_cmd_vel",
    "max_meters": 5.0,
    "max_degrees": 180.0
  }
}
```

### 8.4 模型输出格式

语言模型必须输出严格 JSON：

```json
{
  "reply": "给孩子的简短回复",
  "emotion": "happy|sad|angry|anxious|neutral|excited|unknown",
  "intent": "object_learning_query",
  "safety": {
    "can_move": true,
    "reason": "安全原因"
  },
  "actions": [
    {"type": "forward", "meters": 0.5},
    {"type": "turn", "degrees": 90},
    {"type": "stop"}
  ]
}
```

动作白名单：

| 动作 | 参数 | 单步限制 |
|---|---|---|
| `forward` | `meters` | 0 到 5 米 |
| `backward` | `meters` | 0 到 5 米 |
| `turn` | `degrees` | -180 到 180 度 |
| `wait` | `seconds` | 0 到 3 秒 |
| `stop` | 无 | 停止 |

AI 节点会再次执行安全清洗：

1. 非白名单动作会被丢弃。
2. 距离和角度会被限制在安全范围内。
3. 多步动作按模型输出顺序执行。
4. 末尾多余 stop 会被优化，避免重复制动。

### 8.5 危险物品安全提醒

AI 节点会在读取视觉上下文时独立检查 `objects` 字段。该逻辑不依赖语言模型主动判断，而是作为安全哨兵直接执行：

```text
视觉 objects
  |
  v
危险类别/关键词匹配
  |
  v
同类物品限频去重
  |
  +--> /ai_reply 语音提醒孩子放下并远离
  |
  +--> parent_dashboard_api.py 聚合到家长端危险物品栏目
```

当前风险类别包括：

```text
knife, scissors, fork, baseball bat, hammer, cutter, blade, saw, axe
```

其中 `knife`、`scissors`、`fork`、`baseball bat` 属于 COCO 常见类别；`hammer`、`cutter`、`blade` 等作为后续模型扩展或中文标签兼容项预留。系统默认同一类危险物品 20 秒内不重复语音提醒，避免连续帧触发导致频繁播报。

### 8.6 早教陪护风格

模型提示词要求机器人像早教老师一样说话：

1. 面向孩子，短句、温和、鼓励。
2. 对错误知识先温和纠正，再继续回答。
3. 不迎合错误前提。
4. 情绪低落、紧张或生气时优先安抚。
5. 视觉里有物体且孩子主动问“这是什么”时，结合物体识别结果回答，不再只说支持人脸情绪识别。

```text
/ai_motion_text
```

输出：

```text
/cmd_vel
```

控制流程：

```text
AI actions
  |
  v
转换成中文运动命令
  例如：前进0.5米、左转90度
  |
  v
ssh_voice_control.py 解析距离/角度
  |
  v
计算 Twist.linear.x / Twist.angular.z 和持续时间
  |
  v
通过 SSH 在小车 ROS 环境中发布 /cmd_vel
  |
  v
动作结束后连续发布零速度停止
```

该节点支持：

1. 前进、后退、左转、右转、停止。
2. 阿拉伯数字和中文数字解析。
3. 按速度估算动作持续时间。
4. 停止指令清空队列并中断当前动作。
5. 可选激光雷达避障逻辑，当前主流程默认关闭。

早期 C++ 控制节点：

```text
/home/lzc/catkin_ws/src/robot_voice/src/voice_control.cpp
```

它直接订阅 `/iat_text` 并发布 `/cmd_vel`，适合简单语音控制验证；当前 AI 陪护主链路使用 `/iat_text -> ai_companion_node.py -> /ai_motion_text -> ssh_voice_control.py`。

## 12. 高算力板迁移设计

迁移目标是把视觉推理从当前主控环境迁移到机器人本体或高算力板上，减少网络依赖和端到端延迟。

建议保持以下接口不变：

| 接口 | 保持原因 |
|---|---|

| `/api/latest-result` | 下游获取模型结果接口稳定 |

| `~/.ros/latest_emotion.json` | AI 节点已依赖 |

迁移后的推荐部署：

```text
高算力板

  - 物体检测模型

  - AI 决策
  - 家长端
  - 语音识别与播报
  - 底盘控制
```

也可以进一步把 AI 决策和语音识别都迁移到高算力板，使机器人在无外网环境下具备完整闭环能力。

## 13. 已实现的创新点与算法思路

### 13.1 多模态闭环架构

本项目不是单独做一个识别模型，而是把视觉、语音、语言模型、运动控制和家长端记录串成闭环：

```text
看见环境 -> 听懂孩子 -> 结合上下文思考 -> 说话或动作 -> 记录给家长
```

创新点在于把“识别结果”转化成“陪护行为”：

| 感知结果 | 系统行为 |
|---|---|
| 孩子表情低落、紧张、生气 | 回复时优先安抚，家长端趋势优先提示 |
| 孩子主动问“这是什么” | 结合物体检测结果回答，并计入学习概念 |
| 画面出现危险物品 | 立即语音提醒孩子远离，并在家长端红色记录 |
| 简单运动命令 | 本地规则快速执行 |
| 多步复杂命令 | 交给语言模型拆解成安全动作序列 |

这种设计接近“情感计算 + 社交机器人 + 具身智能”的组合：模型不只是分类，还会影响对话策略、安全策略和家长观察。

### 13.2 双视觉模型协同

视觉侧采用“人脸情绪模型 + 物体检测模型”的双模型结构：

1. YOLO5Face 负责人脸定位，保证表情分类只在有效人脸区域上进行。
2. EmotiEffLib/EmotiEffNet 系列模型负责面部表情分类。
3. 物体检测模型负责 COCO 类别识别，为物体问答、危险物品提醒和家长端记录提供基础。

该思路的亮点是把儿童陪护中最重要的两类视觉信息拆开处理：

| 视觉目标 | 对早教机器人的价值 |
|---|---|
| 人脸情绪 | 判断孩子是否开心、紧张、抗拒或需要安抚 |
| 常见物体 | 支持“这是什么”的认知学习与环境安全提醒 |

后续展示时可以强调：这不是简单的人脸识别，也不是单纯的物体识别，而是“情绪状态 + 环境语义”的联合感知。

### 13.3 最新帧覆盖与实时推理

视频采集采用独立线程持续读取视频源，但只保存最新一帧和递增 sequence，不建立无限队列。上传线程按 `upload-fps` 读取最新帧，同一 sequence 不重复上传。

这一机制的核心思想是实时系统中的“丢弃过期帧”：

| 常规队列方案 | 本项目最新帧覆盖方案 |
|---|---|
| 帧会排队，网络或推理变慢时延迟累积 | 只保留最新画面，过期帧自动覆盖 |
| 更适合离线逐帧分析 | 更适合陪护机器人实时交互 |
| 可能看到几秒前的画面 | 优先保证当前画面 |

对于 MJPEG/RTSP 视频流，这个设计能显著降低缓冲堆积对交互体验的影响。

### 13.4 快慢双路由决策

语音指令不是全部交给语言模型，而是分成两条路线：

```text
简单、高频、确定的指令 -> 本地规则立即执行
复杂、多步、需要理解的指令 -> 语言模型生成结构化计划
```

这相当于机器人上的“快系统 + 慢系统”：

| 路由 | 优点 | 示例 |
|---|---|---|
| 本地快速规则 | 延迟低、稳定、可控 | “前进”“停止”“左转90度” |
| 模型思考 | 能处理多步顺序、知识问答和纠错 | “先前进10米，再左转300度，再跳舞” |

为了安全，语言模型不能直接控制底盘，只能输出 JSON 动作白名单；AI 节点还会进行动作类型检查、距离/角度限幅和顺序执行。这一点适合在答辩中作为“LLM 与机器人安全执行隔离”的亮点。

### 13.5 求知意图门控的概念学习

家长端的“学习概念”不是把所有检测到的物体都算进去，而是需要满足两个条件：

1. 孩子主动表达求知欲，例如“这是什么”“我想知道这个”。
2. 语言模型判断为 `object_learning_query`，且当时视觉 JSON 中存在物体检测结果。

这个设计避免了“摄像头扫过什么都算学过”的误判，更符合早教场景：只有发生了一次孩子主动提问、机器人回答的认知互动，才记录为学习成果。

### 13.6 风险优先的情绪趋势分析

家长端情绪分析不按最高频情绪简单下结论，而是设置关注优先级：

```text
生气 / 低落 / 抗拒 / 紧张
  >
开心 / 惊讶
  >
平静 / 无明显表情
```

这样可以避免“多数时间平静”掩盖短时间但重要的负面情绪。报告展示时可以称为“风险优先的儿童情绪观察策略”。它不做医学诊断，只提供家长陪护观察线索。

### 13.7 危险物品安全哨兵

危险物品提醒采用规则安全哨兵，而不是完全依赖语言模型：

1. 视觉模型输出 `objects`。
2. 安全哨兵匹配刀具、剪刀、叉子、球棒、锤子等危险类别。
3. 语音播报提醒孩子放下并远离。
4. 家长端记录到红色“危险物品”栏目。

这类逻辑适合儿童场景，因为安全提醒应当稳定、可解释、可测试，不应该让语言模型每次自由判断。

### 13.8 家长端长期观察与记忆曲线雏形

家长端已经具备三条可扩展记录线：

| 记录线 | 当前能力 | 后续可扩展 |
|---|---|---|
| 情绪曲线 | 记录当天情绪点和趋势摘要 | 周/月趋势、异常情绪聚类 |
| 对话时间线 | 记录孩子与机器人的对话 | 主题提取、兴趣变化分析 |
| 学习概念 | 记录主动求知产生的物体概念 | 复习次数、遗忘曲线、掌握度评分 |

因此项目后续可以自然升级为“儿童状态观察 + 兴趣学习档案 + 安全事件记录”的家长端系统。

### 13.9 可迁移的本地模型服务接口

视觉模型服务与上层系统通过 HTTP 和 JSON 解耦：

| 接口或文件 | 作用 |
|---|---|
| `/api/frame` | 接收摄像头帧 |
| `/api/latest-result` | 输出最新推理结果 |
| `outputs/latest_emotion.json` | 提供给视觉前端和家长端 |
| `~/.ros/latest_emotion.json` | 提供给 AI 节点 |
| `/vision/latest` | 面向前端和下游服务的统一 API |

这种接口稳定性让项目未来迁移到高算力板时，只需要替换推理服务部署位置，不需要重写 ROS、家长端和语音控制链路。

## 14. 可对标文献与后续展示亮点

本节列出项目中已经使用或可作为后续优化依据的相关算法思想。它们可以在论文、答辩 PPT 或项目展示中作为技术依据。

### 14.1 实时目标检测：YOLO 系列

YOLO 的核心思想是把目标检测建模为一次前向推理即可得到边界框和类别概率的回归问题，强调实时性。该思路适合机器人在线视觉，因为机器人不需要离线精细分析每一帧，更需要低延迟地知道“眼前有什么”。

本项目可对标点：

| 文献思想 | 项目落点 |
|---|---|
| 单阶段实时检测 | 物体检测模型输出 COCO 类别 |
| 端到端图像到框和类别 | `objects` 统一进入视觉 JSON |
| 实时检测服务化 | 后续迁移到高算力板本地推理 |

参考：Redmon et al., *You Only Look Once: Unified, Real-Time Object Detection*, arXiv:1506.02640, https://arxiv.org/abs/1506.02640

### 14.2 人脸检测：YOLO5Face

YOLO5Face 将通用 YOLOv5 检测器优化到人脸检测任务，论文中包含人脸关键点回归头、骨干网络和特征金字塔等改动，并强调 VGA 图像和嵌入式/移动设备上的实时能力。

本项目可对标点：

| 文献思想 | 项目落点 |
|---|---|
| 把人脸检测看作特定目标检测任务 | 使用 YOLO5Face 定位人脸 |
| 面向实时/嵌入式部署 | 未来高算力板部署 |
| 检测后再做表情分类 | 形成“检测 + 分类”的两级视觉管线 |

参考：Qi et al., *YOLO5Face: Why Reinventing a Face Detector*, arXiv:2105.12931, https://arxiv.org/abs/2105.12931

### 14.3 表情识别：EmotiEffNet 与情感计算

情绪识别属于情感计算方向。情感计算强调机器识别、解释和响应人的情绪状态；在早教陪护机器人中，它对应“根据孩子情绪调整回复和提醒策略”。

EmotiEffNet 相关工作使用预训练卷积网络提取帧级表情特征，并结合时序后处理改善视频表情识别效果。该方向与本项目后续优化高度相关：当前系统已经记录连续情绪点，未来可以加入时间平滑、短时窗口投票或时序模型，减少单帧误判。

本项目可对标点：

| 文献思想 | 项目落点 |
|---|---|
| 面部表情识别 | EmotiEffLib 情绪分类 |
| 视频帧级特征 | 当前每次视觉 JSON 都可作为时间序列样本 |
| 时序平滑后处理 | 后续可降低情绪抖动 |
| 情感计算 | 家长端情绪趋势与机器人安抚策略 |

参考：

- Savchenko, *EmotiEffNet Facial Features in Uni-task Emotion Recognition in Video at ABAW-5 competition*, arXiv:2303.09162, https://arxiv.org/abs/2303.09162
- Picard, *Affective Computing*, MIT Press, 1997

### 14.4 离线语音识别：Vosk/Kaldi

Vosk 是面向离线和轻量设备的语音识别工具，支持流式 API 和中文等多语言模型。它适合机器人端使用，因为儿童陪护机器人需要在网络不稳定时仍能听懂基础指令。

本项目可对标点：

| 文献/工程思想 | 项目落点 |
|---|---|
| 离线 ASR | Jetson 麦克风音频通过 Vosk 中文模型识别 |
| 流式识别 | `ssh_arecord_vosk_iat.py` 持续输出 `/iat_text` |
| 词表适配 | 唤醒词“灵犀”及误识别别名归一 |

参考：Vosk Offline Speech Recognition API, https://alphacephei.com/vosk/

### 14.5 LLM 推理与行动：ReAct / ReSpAct 思路

ReAct 类方法强调语言模型在任务中同时生成推理和行动，适合需要与环境交互的智能体。ReSpAct 进一步把 Reason、Speak、Act 结合起来，更接近会说话、会动作、能和用户互动的机器人。

本项目没有让模型输出自由形式的动作，而是采用更安全的结构化版本：

```text
用户语音 + 视觉上下文 + 记忆
  |
  v
语言模型输出 JSON plan
  |
  v
动作白名单与参数限幅
  |
  v
语音回复 / 小车运动
```

本项目可对标点：

| 文献思想 | 项目落点 |
|---|---|
| Reason + Act | 语言模型生成回复和动作计划 |
| Speak + Act | `/ai_reply` 与 `/ai_motion_text` 双输出 |
| 可解释轨迹 | `/ai_plan` 和 `~/.ros/ai_companion_latest_plan.json` 留存 |
| 外部环境交互 | 视觉上下文、ROS 控制、家长端记录 |

参考：

- Yao et al., *ReAct: Synergizing Reasoning and Acting in Language Models*, arXiv:2210.03629, https://arxiv.org/abs/2210.03629
- Dongre et al., *ReSpAct: Harmonizing Reasoning, Speaking, and Acting Towards Building Large Language Model-Based Conversational AI Agents*, arXiv:2411.00927, https://arxiv.org/abs/2411.00927

### 14.6 社交机器人与早教陪护

教育类社交机器人研究通常关注三个问题：

1. 机器人如何作为助教、同伴或陪伴者参与学习活动。
2. 机器人如何根据儿童状态调整语言、动作和互动节奏。
3. 家长或教师如何从机器人记录中理解孩子的学习和情绪变化。

本项目的亮点是把这三件事都落到了工程链路中：

| 教育机器人关注点 | 项目实现 |
|---|---|
| 互动陪伴 | 早教老师风格回复 |
| 情绪适应 | 根据情绪识别结果调整安抚和趋势提醒 |
| 学习记录 | 主动求知才计入学习概念 |
| 安全陪护 | 危险物品语音提醒和家长端红色记录 |

参考：Belpaeme et al., *Social robots for education: A review*, Science Robotics, 2018, https://doi.org/10.1126/scirobotics.aat5954

### 14.7 后续可优化成论文亮点的方向

| 方向 | 可采用的算法思路 | 价值 |
|---|---|---|
| 情绪曲线更稳定 | 滑动窗口投票、指数平滑、HMM/时序分类 | 降低单帧表情误判 |

## 15. 技术特点总结

1. 视觉模型采用“人脸情绪 + 物体检测”的双模型结构。
2. 视觉结果统一落到 JSON，降低前端、AI 和家长端之间的耦合。
3. 视频读取使用最新帧覆盖机制，优先保证实时性。
4. AI 决策采用双路由：简单动作本地快速处理，复杂意图交给语言模型。
5. 动作执行使用白名单和参数限幅，避免语言模型直接输出危险控制。
6. 家长端不做医学诊断，只做陪护观察和趋势提醒。
7. 学习概念只在孩子主动求知时记录，符合早教场景。
8. 危险物品识别采用规则安全哨兵，触发语音提醒并写入家长端红色栏目。
9. 系统保留 ROS 话题接口，便于后续换模型、换板子、换前端而不重构全部链路。

## 16. 后续优化方向

1. 将本地视觉推理服务封装为高算力板开机自启动服务。
2. 统一视觉服务字段命名，减少兼容字段。
3. 增加物体类别中文映射，使 AI 回复更自然。
4. 对学习概念增加“复习次数”和“遗忘曲线”。
5. 家长端增加按周/月汇总的情绪趋势。
6. 对底盘控制加入更完整的安全状态机和传感器融合避障。
7. 在无外网部署时，将语言模型替换为本地大语言模型推理服务。
8. 对危险物品提醒增加多帧确认和目标跟踪，减少单帧误报。
